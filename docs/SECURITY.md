# 安全模型

## 信任边界

| 对象 | 风险 | 现状 |
|---|---|---|
| 站点脚本 | 可发起网络请求、读取页面数据 | 用户自己编写 |
| JS 扩展包 | 与 App 同上下文执行 | 不是强沙箱 |
| Python 预编译模块 | 原生代码 | 只在模块商店安装 |
| 热修复 JS | 页面级执行 | 有签名，但私钥在发布者手中 |
| 外部链接 | 可能钓鱼 | 已改为系统浏览器打开 |

## 已做

- 热修复 RSA-SHA256 验签；
- 无签名拒绝；
- 热修复回滚；
- 扩展包权限声明与安装确认；
- 扩展包升级/卸载清理贡献点；
- 规则源签名校验；
- 外链不劫持 SPA；
- 构建产物扫描 R18/备份文件。

## 未做

- 扩展包强沙箱；
- 桥能力分级：`JsBridge` / `TermBridge` 仍对页面同上下文暴露，扩展/脚本理论上可访问；
- 模块商店的 wheel 哈希/签名校验；
- 扩展包签名（当前只有 manifest 校验和权限声明）；
- 脚本网络权限隔离；
- 生产签名/上架签名。

## 当前发布策略

- APK 通过 GitHub Releases 分发，不放进 Git 工作树；
- 仓库不内置任何站点规则或成人内容；
- 许可证：AGPL-3.0。

## 建议

- 只安装可信扩展包；
- 不要在脚本里硬编码敏感 Cookie；
- 公开分享脚本前删除 Cookie/Token；
- 正式分发使用自己的生产 keystore。
